# GlassCAD

Локальное веб-приложение для проектирования душевых кабин и изделий из стекла:
**замер → конструкция → комплектующие → расчёт стекол → фурнитура → обработка → производственные чертежи → PDF/DXF**.

Работает без облака на Raspberry Pi или любом Linux-компьютере; открывается из браузера
с любого компьютера локальной сети: `http://<ip>:8091`.

Версия: см. `app/__init__.py` (и «Настройки» в интерфейсе).

---

## Установка (Raspberry Pi OS / Debian / Ubuntu)

```bash
sudo ./deploy/install.sh
```

Что делает скрипт:

| Что | Где |
|---|---|
| Код приложения | `/opt/glasscad` |
| Python-окружение | `/opt/glasscad/venv` |
| **Данные** (БД SQLite, DXF фурнитуры, логотип) | `/var/lib/glasscad` |
| Резервные копии БД | `/var/lib/glasscad/backups` |
| Сервис автозапуска | `systemd: glasscad.service` |

Управление сервисом:

```bash
sudo systemctl status glasscad
```

```bash
journalctl -u glasscad -f
```

### Обновление без потери данных

Скопируйте новую версию на устройство (папкой или архивом `.tar.gz`) и запустите:

```bash
sudo ./deploy/update.sh
```

Скрипт: делает бэкап БД и загруженных файлов → останавливает сервис → заменяет код
(старый сохраняется в `/opt/glasscad.prev`) → ставит зависимости → запускает.
При старте приложение само применяет миграции схемы БД (перед этим — ещё один бэкап).
Если новая версия не ответила — код автоматически откатывается.

Ручная резервная копия (можно поставить в cron):

```bash
sudo /opt/glasscad/deploy/backup.sh daily
```

## Как работать

1. **Заказы → Новый заказ.** Номер присваивается автоматически, статус — от «Черновика» до «Завершён».
2. **Добавить изделие.** Выберите режим:
   * **Быстрый** — замер проёма + шаблон конструкции + комплект фурнитуры → стекла рассчитаны сразу;
   * **Конструктор** — замер + шаблон, фурнитура и обработка добавляются вручную;
   * **Ручной** — размеры каждого стекла задаются вручную (зеркала, нестандарт).
3. **Конструктор**: слева — дерево (стекла, фурнитура, профили, обработка, оси, доп. позиции),
   в центре — CAD-холст (колесо — масштаб, перетаскивание фона — сдвиг, `F` — вписать),
   справа — точные свойства выбранного объекта. Перетаскивание отверстий/фурнитуры мышью меняет
   отступ от выбранной базы, а не абсолютные координаты. `Ctrl+Z / Ctrl+Y`, `Ctrl+D` — дублировать, `Delete`.
4. **PDF** (для клиента / для производства / полный) и **DXF** (каждое стекло, zip, конструкция целиком).

### Правила расчёта

* Все размеры в **мм**, начало координат — левый нижний угол проёма, ось Y вверх.
* Ширина проёма = минимальная из «сверху/центр/снизу», высота — минимальная из «слева/справа»
  (при разнице > 5 мм выводится предупреждение).
* **Общий верх**: верх всех стекол на одной линии, перепады (дверь ↔ пол 12 мм, профиль) — снизу.
  Есть «Выровнять по верху с…» для отдельных стекол.
* Ширина стекла: *Авто* (остаток проёма), *Число*, *Формула* (`A / 2 + 30`; переменные `L`, `A`, `H`, `dl`, `dr`, `T`).
  «Ручная корректировка» всегда перекрывает расчёт.
* Вычеты кромок по приоритету: значение на кромке → зазор петли из базы → профиль
  (`глубина − посадка + монтажный запас`) → правила зазоров изделия.
* Форма стекла: прямоугольник, четырёхугольник по 4 сторонам и одному углу (остальные вершины
  вычисляются; невозможная геометрия — ошибка), произвольный многоугольник.

### Фурнитура как узел

Модель фурнитуры (Библиотека → Фурнитура) состоит из **сторон** A, B, C…; каждая сторона —
обработка одного стекла:

1. Загрузить DXF (нарисованный в AutoCAD).
2. Отметить рабочие линии (**Обработка**), вспомогательные (**Вспомогательная**) и лишнее (**Не использовать**).
3. Указать **край стекла** (вспомогательный отрезок) и с какой стороны от него стекло.
4. Указать **точку привязки** — только по объектным привязкам (конец, середина, центр, квадранты, середина дуги).
5. «Проверить на стекле» — узел показывается на двух тестовых стеклах.

Вырез, пересекающий кромку, **становится частью контура стекла** (линия кромки в месте выреза
удаляется) — на холсте, в DXF и PDF. Дуги сохраняются как дуги (bulge), а не ломаная.
Вспомогательная геометрия в производственный DXF не попадает.

### DXF-экспорт

Масштаб 1:1, мм. Слои: `GLASS` (контур), `CUT` (внутренние контуры), `HOLES`, `AXIS`, `DIM`, `TEXT`, `AUX`.

## Архитектура

```
app/
  geometry/      формулы, четырёхугольник по сторонам, примитивы, контур с вырезами (shapely + восстановление дуг)
  engine/        модель изделия, расчёт по замеру (resolve), обработка, фурнитура, размеры, спецификация,
                 шаблоны конструкций и комплекты
  export/        dimlayout (общая раскладка размеров), dxf_export, pdf (reportlab, вектор)
  api/           FastAPI: orders, products, library (+DXF), system (настройки, бэкапы)
  hardware_dxf.py  импорт DXF фурнитуры, объектные привязки
  db.py          SQLite, миграции (только добавление), авто-бэкап перед миграцией
  seed.py        категории, встроенные шаблоны, демо-набор (помечен «Демо»)
static/          интерфейс (vanilla JS, ES-модули, без сборки)
deploy/          install.sh, update.sh, backup.sh, glasscad.service
tests/
```

* **Единая геометрическая модель**: `engine.resolve()` возвращает стекла с реальными контурами,
  отверстиями и семантическими размерами; холст, PDF и DXF строятся из неё.
* **ID вместо имён**: у всех объектов внутренний неизменяемый uuid; переименование ничего не ломает.
  Всё создаваемое можно переименовать, изменить, дублировать и удалить.
* **Расширяемость**: библиотека — одна таблица с коллекциями (`library.collection`), изделие хранит
  JSON-описание; типы изделий (зеркало, фартук, перегородка, ограждение) уже предусмотрены в модели.
* Новая версия схемы БД = новая запись в `MIGRATIONS` (`app/db.py`); существующие данные не удаляются.
